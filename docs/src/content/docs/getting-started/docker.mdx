title: Docker setup
description: Run Aurral in Docker and connect it to the shared media filesystem.
---

Aurral runs in Docker. It needs a Postgres database and two mounts:

- `/config` for the background job queue, cached artwork, staging files, and diagnostic reports.
- A shared media mount for the Lidarr library, completed downloads, and Aurral output.

Settings, users, sessions, the library index, and job history live in Postgres, not in `/config`.

Read [Filesystem and mounts](/getting-started/storage/) before you create the Compose file. Aurral must share a media mount with Lidarr, your download clients, and Navidrome, Plex, or Jellyfin.

## Minimal Compose file

```yaml
services:
  aurral:
    image: ghcr.io/lklynet/aurral:latest
    restart: unless-stopped
    ports:
      - "3001:3001"
    environment:
      - PUID=${PUID:-1000}
      - PGID=${PGID:-1000}
      - DATABASE_URL=postgres://aurral:${POSTGRES_PASSWORD:-aurral}@postgres:5432/aurral
    volumes:
      - ${MEDIA_ROOT:-/srv/media}:/data
      - ./config:/config
    depends_on:
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      - POSTGRES_USER=aurral
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-aurral}
      - POSTGRES_DB=aurral
    volumes:
      - ./postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U aurral -d aurral"]
      interval: 5s
      timeout: 3s
      retries: 10
```

Aurral keeps settings, users, the library index, and job history in Postgres. The `postgres` service above is enough for a home install; to use a server you already run, drop it and set `DATABASE_URL` to that server instead. Postgres 14 or newer with the `pg_trgm` extension is required (Aurral creates the extension on first start, which needs a superuser or the `CREATE` privilege on the database).

Replace `/srv/media` with the host directory that Lidarr already uses. Keep `:/data` as the container side of the mount so every media service sees the same paths.

For example, the host folder `/srv/media/downloads/aurral` is `/data/downloads/aurral` inside Aurral. Set the Downloads Folder to the container path in **Settings > Download clients**, not to the host path.

`/config` holds the background job queue (`honker.db`), cached images, download staging, and diagnostic reports. Logs go to the container's stdout. Do not share `/config` with another service.

Back up both `./config` and `./postgres`. Losing the Postgres volume loses settings, users, and the library index.

## Start Aurral

```bash
docker compose up -d
```

1. Open `http://localhost:3001`.
2. Create the admin account.
3. Connect Lidarr.
4. Set the Downloads Folder path and run the storage checks.

Continue with [First run](/getting-started/first-run/).

## Which image tag to use

| Tag | Contents | Use it when |
| --- | --- | --- |
| `latest` | The newest stable release | You want a tested release. |
| `2.4.0`, `2.4`, `2` | An exact version, or the newest release in that line | You pin versions or need to roll back. |
| `nightly` | Every change merged since the last release | You want fixes and features early and can report bugs. |
| `pr-<number>` | The preview image for an open pull request | You were asked to test a proposed change. |

Aurral checks for a newer build in your channel. When one exists, an update icon appears in the top-right area. Select it to preview the release changes and open the GitHub release or commit list.

Non-stable channels also mark the sidebar.

:::caution
`nightly` is not a stable release. Back up `./config` and `./postgres` before switching to it.

Nightly images currently support `linux/amd64` only. On ARM, use `latest` or a versioned stable tag.
:::

For the current Nightly scope, see the [Release Readiness issues](https://github.com/lklynet/aurral/issues?q=is%3Aissue+label%3Arelease-readiness+sort%3Aupdated-desc). The latest issue is pinned at the top and lists the current Nightly candidate and included changes.

## Test a pull request preview

When a pull request has a preview image, its GitHub conversation contains the exact `pr-<number>` image tag and test instructions.

1. Back up `./config` and `./postgres`.
2. Temporarily change the Aurral image to the preview tag.
3. Run `docker compose pull aurral && docker compose up -d aurral`.
4. Test the behavior changed by the pull request.
5. Restore the image reference that you used before testing.
