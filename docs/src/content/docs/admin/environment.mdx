Use the web UI for most settings. Use these variables for Docker deployment settings.

## Mounts and permissions

| Variable | Purpose |
| -------- | ------- |
| `PUID` / `PGID` | Run the container as the user that owns mounted folders. `AURRAL_UID` / `AURRAL_GID` are accepted as aliases and take precedence. |
| `AURRAL_DATA_DIR` | Override app data directory. Default `/config`. |
| `DOWNLOAD_FOLDER` | Initial Downloads Folder path. Prefer **Settings > Download clients > Downloads Folder > Path**. Use an absolute path under your media mount. `PLAYLIST_FOLDER` and `WEEKLY_FLOW_FOLDER` are older names for the same setting and win over `DOWNLOAD_FOLDER` when set. |
| `FILE_BROWSE_ROOTS` | Comma-separated directories the folder picker in Settings may browse. Default: `/data`, the data directory, the Downloads Folder, and the working directory, whichever exist. |
| `PORT` | HTTP port the server listens on. Default `3001`. |
| `JSON_BODY_LIMIT` | Maximum JSON request body. Default `5mb`. |

## Database

Aurral stores everything except the background job queue in Postgres.

| Variable | Purpose |
| -------- | ------- |
| `DATABASE_URL` | **Required.** Postgres connection string, for example `postgres://aurral:secret@postgres:5432/aurral`. The database must exist; Aurral creates its tables and the `pg_trgm` extension on first start. |
| `AURRAL_PG_POOL_MAX` | Maximum pooled connections per process. Default `10`. The library scan worker thread opens its own pool. |
| `AURRAL_PG_APPLICATION_NAME` | `application_name` reported to Postgres. Default `aurral`. |
| `AURRAL_HONKER_DB_PATH` | Location of the SQLite file backing the background job queue. Default `<data dir>/honker.db`. |
| `AURRAL_MEMORY_WARN_MB` | Log a warning when the process RSS passes this many megabytes (at most every ten minutes). Default `1536`. The image also sets `NODE_OPTIONS=--max-old-space-size=2048` so the Node heap cannot grow without bound; override `NODE_OPTIONS` to change it. |
| `LIDARR_BULK_TIMEOUT_MS` | Timeout for the bulk Lidarr reads a library scan makes (the full album list, per-artist track and file lists). Default `180000`. These reads do not retry, and a failure keeps Aurral off Lidarr for ten minutes. |
| `LIBRARY_WATCH_FULL_SCAN_INTERVAL_MS` | Minimum time between full Lidarr pulls triggered by the file watcher. Default `3600000` (one hour). Changes the watcher can map to known artists re-index only those artists; everything else waits for the next allowed full pull or a Lidarr webhook. |

### Migrating from SQLite

Installs created before the Postgres switch keep their data in `aurral.db` inside the data directory. Copy it into Postgres once.

Stop the running app first so nothing writes to `aurral.db` during the copy, then preview the migration and run it:

```bash
docker compose stop aurral
docker compose run --rm aurral node backend/scripts/migrateSqliteToPostgres.js --dry-run
docker compose run --rm aurral node backend/scripts/migrateSqliteToPostgres.js
docker compose up -d aurral
```

`docker compose run` starts a separate throwaway container from the same service definition, so it works while the app itself is stopped, and it starts the `postgres` service if it is not already up.

The script reads `aurral.db` from the data directory (override with `--sqlite <path>`), applies the Postgres schema, and inserts every row it finds in batches, skipping rows that already exist and resetting each id sequence past the highest copied row. Add `--dry-run` to see row counts without writing, or `--truncate` to empty the Postgres tables first and start over. Running it twice is safe.

Every table present in both databases is copied, including genres and search documents. The generated `search_text` column is rebuilt by Postgres as rows arrive. The background job queue keeps its own `honker.db` file; leave it in place. `aurral.db` is left untouched; delete it once you have confirmed the migrated install.

## Tuning

Defaults suit most installs. Change these only when diagnosing load or latency.

| Variable | Purpose |
| -------- | ------- |
| `LIBRARY_WATCH_DEBOUNCE_MS` | Quiet period after the last filesystem change before the watcher re-indexes. Default `120000` (two minutes). |
| `LIBRARY_WATCH_MAX_WAIT_MS` | Longest a burst of changes can delay re-indexing. Default `600000` (ten minutes). |
| `AURRAL_STORAGE_HEALTH_CACHE_MS` | How long **Storage health** results are cached. Default `60000`. |
| `AURRAL_MEDIA_HEALTH_SAMPLE_LIMIT` | Number of media files sampled by the native-playback storage check. Default `500`. |
| `AURRAL_WORKER_SUPERVISOR_POLL_MS` | How often the worker supervisor checks queues. Default `60000`. |
| `AURRAL_WORKER_IDLE_STOP_MS` | Idle time before a background worker stops. Default `60000`. |
| `AURRAL_HONKER_WATCHER_POLL_MS` | Poll interval for the job queue watcher, 1 to 1000. Default `25`. |
| `AURRAL_DISCOVERY_USER_REFRESH_DELAY_SECONDS` | Delay between per-user discovery refreshes, 5 to 3600. Default `10`. |
| `AURRAL_DISCOVERY_PLAYLIST_BUILD_CONCURRENCY` | Discover playlists built in parallel, 1 to 6. Default `3`. |

## Path mappings

| Variable | Purpose |
| -------- | ------- |
| `PATH_MAPPINGS` | Translate paths for mixed Windows and Docker setups. Use the format `remote\|local`. Separate multiple mappings with `;`. To limit a mapping to one source, use `source\|remote\|local`. Aurral applies these mappings at runtime. Edit them under **Settings > Download clients > Remote Path Mappings**. |

## Authentication

| Variable | Purpose |
| -------- | ------- |
| `TRUST_PROXY` | Express `trust proxy` value. Default `1` (trust one proxy hop). Set `false` when no proxy sits in front of Aurral, a number for more hops, or `true` to trust every hop. |
| `AURRAL_PUBLIC_URL` | Public origin used to build the Last.fm account-link callback (for example, `https://aurral.example.com`). OIDC uses `OIDC_REDIRECT_URI`; Spotify uses `SPOTIFY_OAUTH_REDIRECT_URI`. |
| `AUTH_USER` / `AUTH_PASSWORD` | Legacy single-account login. `AUTH_USER` defaults to `admin`; `AUTH_PASSWORD` accepts a comma-separated list of accepted passwords and also enables Subsonic token auth for that user. A password saved in **Settings > General** takes precedence. Prefer user accounts. |
| `AUTH_PROXY_ENABLED` | Enable reverse-proxy authentication. Default header `x-forwarded-user`. |
| `AUTH_PROXY_HEADER` | Custom header that contains the authenticated username. |
| `AUTH_PROXY_DOMAIN` | Origin of your forwardAuth login page (for example, `https://auth.example.com`). Aurral adds it to the `connect-src` content security policy so pages can reach your authentication origin. |
| `AUTH_PROXY_TRUSTED_IPS` | Comma-separated proxy IP allowlist for authentication headers. You must set it when you enable proxy authentication. Without it, a direct client can use the identity header to impersonate users. |
| `AUTH_PROXY_LOGOUT_URL` | Your proxy or IdP logout endpoint. For Authentik single-application forward auth, use `https://aurral.example.com/outpost.goauthentik.io/sign_out`. This value ends the proxy session when you log out of Aurral. Aurral hides its **Log out** control while proxy authentication is on and this value is unset. |
| `AUTH_PROXY_DEFAULT_ROLE` | Role for proxy-auth users who do not otherwise have the admin role: `user` or `admin`. Aurral evaluates the role on every request. |
| `AUTH_PROXY_ADMIN_USERS` | Comma-separated usernames that get the admin role. Aurral checks the list on each request. If you remove a username, Aurral changes that user on the next request. |
| `AUTH_PROXY_ROLE_HEADER` | Optional header that contains the user's group membership (for example, Authelia's `Remote-Groups`). Usually, this is a comma-separated list. Aurral compares it with `AUTH_PROXY_ADMIN_GROUPS` on every request. |
| `AUTH_PROXY_ADMIN_GROUPS` | Comma-separated group names that give the admin role. Aurral compares these names with `AUTH_PROXY_ROLE_HEADER`. A group named `admin` has no special function unless you list it here. |
| `OIDC_ENABLED` | Enable native OpenID Connect login. |
| `OIDC_ISSUER` | Identity provider issuer URL used for OIDC discovery. |
| `OIDC_CLIENT_ID` | OIDC client ID. |
| `OIDC_CLIENT_SECRET` | OIDC client secret. |
| `OIDC_REDIRECT_URI` | Exact callback URL registered with your IdP. Must be `https://<your-aurral-host>/sso/callback`. |
| `OIDC_SCOPES` | Space-separated scopes. Default `openid profile email`. |
| `OIDC_USERNAME_CLAIM` | Claim used as the Aurral username. Default `preferred_username`. Falls back to `email` when that claim is missing. |
| `OIDC_DEFAULT_ROLE` | Role for OIDC users who are not otherwise granted admin: `user` or `admin`. |
| `OIDC_ADMIN_USERS` | Comma-separated usernames that get the admin role at OIDC login. |
| `OIDC_GROUPS_CLAIM` | Optional ID-token claim that contains group membership. |
| `OIDC_ADMIN_GROUPS` | Comma-separated group names that grant the admin role when present in `OIDC_GROUPS_CLAIM`. |
| `OIDC_LOGOUT_URL` | Optional IdP logout URL. When set, Aurral redirects there after clearing the local session. |
| `OIDC_DOMAIN` | Optional IdP origin added to the `connect-src` content security policy. |
| `SESSION_EXPIRY_HOURS` | Session lifetime in hours for password login, proxy auth, and native OIDC. Default `720` (30 days). |

## Cross-origin clients

| Variable | Purpose |
| -------- | ------- |
| `CORS_ORIGIN` | Comma-separated browser origins allowed to call Aurral's JSON API. Browser Subsonic clients do not need this setting. |

## Logging

| Variable | Purpose |
| -------- | ------- |
| `AURRAL_VERBOSE_LOGS` | Set to `true` to include routine and debug server logs. Regular logs show startup messages, warnings, and errors. |

## Image proxy

| Variable | Purpose |
| -------- | ------- |
| `AURRAL_IMAGE_PROXY_MAX_BYTES` | Maximum library-art image-proxy disk-cache size in bytes. The default is `268435456` (256MB). Aurral removes the oldest entries first. When Aurral serves an image, it updates the age of that image. |

## Lidarr

The URL and API key are normally set in **Settings > Lidarr**. The variables below are fallbacks and tuning knobs.

| Variable | Purpose |
| -------- | ------- |
| `LIDARR_URL` / `LIDARR_API_KEY` | Used when the web UI has no Lidarr connection saved. Saved settings take precedence. |
| `LIDARR_TIMEOUT_MS` | Timeout for ordinary Lidarr API calls. Default `30000`. |
| `LIDARR_INSECURE` | Set `true` to accept a self-signed TLS certificate on the Lidarr URL. |
| `LIDARR_CIRCUIT_DISABLED` | Set `true` to disable the circuit breaker that pauses Lidarr calls for one minute after three consecutive failures (ten minutes after a failed bulk read). |

## External providers

| Variable | Purpose |
| -------- | ------- |
| `AURRAL_LASTFM_TIMEOUT_MS` | Last.fm API timeout in milliseconds. Default `15000`. Increase this value if focus playlists have no tracks and logs show `ECONNABORTED`. |
| `LASTFM_API_KEY` / `LASTFM_API_SECRET` | Fallback Last.fm credentials when none are saved in **Settings > Connect > Last.fm**. |
| `TICKETMASTER_API_KEY` | Fallback Ticketmaster consumer key for nearby shows when none is saved in **Settings > Connect > Ticketmaster**. |
| `CONTACT_EMAIL` | Contact address sent in the MusicBrainz user agent. Default `user@example.com`. |
| `BRAINZMASH_BASE_URL` | Alternative metadata server. Default `https://lidarrapi.brainzmash.cc`. The URL saved at `/settings/metadata` takes precedence. |

## Spotify playlist import

These variables change the shared Lidarr Spotify OAuth proxy. The default values are correct for most installations.

| Variable | Purpose |
| -------- | ------- |
| `SPOTIFY_CLIENT_ID` | OAuth client ID. |
| `SPOTIFY_OAUTH_REDIRECT_URI` | Authorization redirect. Default `https://spotify.lidarr.audio/auth`. |
| `SPOTIFY_OAUTH_RENEW_URI` | Token refresh endpoint. Default `https://spotify.lidarr.audio/renew`. |

```yaml
environment:
  - PUID=1000
  - PGID=1000
  - TRUST_PROXY=true
```
